# RoboDojo：Wan-MoT 改进方向与实验设计

状态：研究方案，尚未实现或验证。更新日期：2026-10-30。

## 目标与约束

以 RoboDojo 闭环成绩和公开可复现为目标，在现有 EasyWAM 基础上探索有效的世界动作模型改进。首个基线为 Wan2.2-TI2V-5B + MoT、joint14、三相机，视频与动作专家全参数训练，不使用 LoRA。当前硬件为单卡 A800 80GB；完成短训练、保存恢复和仿真闭环验证后，再决定是否租用多卡。

先建立可信基线，再逐项验证机制。模型规模、数据、训练量、注意力模式、推理策略都可能影响成绩，不能因为都叫 MoT 就认为差异来自某一个因素。尚无充分证据将 VPP2 的 RoboDojo 领先单独归因于历史帧。

## 当前实现的控制路径

当前 `src/model/easywam_mot.py` 默认采用 `first_frame_causal`：训练时动作 token 可读取首帧和动作序列，不能直接读取未来视频 token；未来视频预测通过训练损失影响视频骨干。推理时将当前图像编码，预填充视频 KV cache，然后对动作序列逐步去噪，不逐步生成未来视频。`configs/benchmark/sim_robodojo.yaml` 默认预测 32 步动作、执行 24 步后重规划；以实际解析配置为准。

这条路径与 Fast-WAM 的“视频联合训练、动作直接推理”思路相近，但不能据此声称本项目复现了 Fast-WAM 的模型或成绩。[Fast-WAM](https://arxiv.org/abs/2603.16666) 报告，视频联合训练是其受控实验中的重要因素。

**基线前置问题：** `experiments/robodojo/easywam_policy/deploy_policy.py` 的策略构造器目前把 `load_text_encoder` 写到模型配置顶层；当前 `runtime._create_easywam_mot` 接口不接受该顶层参数，而字段应在 `model.backbone` 下。此前的配置解析测试没有覆盖真实策略实例化。应先修正字段并补充实际构造路径测试，再开展模型比较。完整模型前向/反向、保存恢复和 Isaac Sim 评测仍未验证。

## 方向一：近期状态和已执行动作

### 假设

相同的当前关节状态可能对应接近、停顿或撤回等不同动态。最近的状态变化和已执行命令可能帮助动作专家判断运动趋势、改善 chunk 边界连续性。历史动作也可能与当前状态高度冗余；它不能单独解决“物体刚才放在哪里”等视觉记忆问题。

### 最小实验

以最近 8 步为起点，分别输入：历史状态及状态变化、历史已执行动作、两者组合。用小 MLP 或浅层时序编码器压成少量条件 token，只供 ActionDiT 使用，不作为待去噪动作计算损失；加类型、相对时间和有效长度编码。8 步仅是初始试验值。

需要修改数据窗口和 episode 边界处理、动作专家条件输入与 attention mask、推理 batcher 接口，以及 `experiments/robodojo/easywam_policy/deploy_policy.py` 的逐环境历史管理。推理端只记录真正执行过的命令，不把预测但未执行的 chunk 尾部记入历史；不同 session 和并行环境独立存储并在 reset 时清空。

先核实数据集 `action[t]` 的控制语义及时间对齐，测试首帧 padding、截断、reset、异步延迟和批量环境，确保不跨 episode 或泄漏未来动作。专家历史与模型 rollout 历史存在分布差异；可对照历史 dropout、噪声和后续 rollout 数据，但它们不保证解决偏移。

只有失败回放显示真正的视觉记忆缺口时，再比较少量历史帧或关键事件，而不是默认堆长历史。[BPP](https://arxiv.org/abs/2602.15010) 指出朴素历史条件可能学习到不泛化的相关性；其结论来自其评测任务，并非 RoboDojo 的直接证据。

## 方向二：一次计算的未来相关特征

### 假设与论文依据

当前动作专家推理只读取当前帧。可测试在动作去噪期间复用一次视频前向得到的未来相关特征，是否改善操作决策，而避免多次生成完整未来视频。

[Faster-WAM](https://arxiv.org/abs/2608.04404) 在其受控实验中使用一次前向的未来条件、稀疏交互和多深度 KV 融合，报告分布外泛化收益；其性能和速度不自动适用于本项目。新增未来位置会增加视觉前向计算，是否比当前 MoT 更快需要实测。一次前向得到的是隐特征，不等同于准确预测的未来画面。

### 分阶段实现

1. 以干净当前帧为条件，加入未来位置的噪声 latent，单次视频前向产生特征；动作专家读取并在同一次动作去噪中复用。
2. 训练时覆盖对应的视频噪声条件和注意力规则，并确保推理只使用当前可获得的信息；不能把真实未来帧直接传给动作专家。
3. 将该方案与当前 MoT 在相同预训练初始化、训练样本量、训练种子和评测条件下比较。
4. 若未来条件有价值，再比较逐层读取和稀疏层读取，以及多深度 KV 汇总；注意训练和推理的 mask 必须一致。

代码入口主要是 `src/model/easywam_mot.py` 的 attention mask、训练 loss 和 `infer_action_batch`，以及 `src/model/component/mot.py` 的视频缓存和动作读取。旧 checkpoint 未必适合新的注意力关系；仅改推理开关不足以验证新结构。

另一个低推理开销的对照是未来特征监督：训练时从未来观测获取冻结教师目标，让当前特征预测它，推理时移除预测头。2026-10-27 的新预印本 [JAM](https://arxiv.org/abs/2610.37219) 探索了这一思路；它不是本项目的新颖性证明，亦无本项目 RoboDojo 结果。

## 方向三：更快的动作推理

先测量图像处理/VAE、视频骨干、动作去噪、通信及仿真分别耗时，并分别报告单请求延迟和批量吞吐量。当前已有视觉 KV 复用，减少动作步数的整体收益取决于它占总耗时的比例。

1. 固定 checkpoint 比较 10、6、4 步动作去噪，同时测成功率、各维度得分和 P50/P95 延迟。
2. 测试现有 `torch.compile`、固定形状和缓存是否在目标硬件上有效；包含预热成本和数值一致性检查。
3. 基线可靠后，比较训练 2–4 步学生策略的蒸馏方案，不把简单减少步数视为蒸馏。

[AnyStep-WAM](https://arxiv.org/abs/2609.33748) 研究面向不同步数预算的蒸馏和自适应推理，论文实验使用 LoRA；若遵循本项目不使用 LoRA 的约束，需另行设计和验证，不能直接转述其成本或收益。

[RTC](https://arxiv.org/abs/2506.07339) 让机器人执行旧 chunk 的同时异步生成下一段，并处理两段动作的衔接。它与“历史动作作为模型条件”不同，适合后期真实连续控制；是否提升 RoboDojo 分数取决于仿真与策略等待的时序，不能仅凭缩短墙钟时间推断。

## 数据与预训练

[VPP2](https://arxiv.org/abs/2610.10270) 包含操作视频持续预训练、事件级数据和单步视觉规划；公开 RoboDojo 配方还包含历史和关键阶段采样等因素。它们并未提供可以把榜单差距只归因于某一因素的等条件证据。

[OpenWAM](https://openwam.stanford.edu/) 在 Wan2.2-5B 基础上先进行机器人视频预训练，再研究视频与动作交互。对有限预算团队，检查可用的机器人视频预训练权重、网络结构/attention 兼容性、许可证和训练数据是否符合评测规则，可能比自行复刻大规模预训练更实际。动作专家参数规模和 checkpoint 映射须单独核对，不能假设同名 Wan 模型可直接加载。

训练层面可对照视频骨干较小学习率、动作专家较大学习率、任务均衡和关键操作阶段采样。这些是待验证假设；应控制总训练样本量并同时记录 GPU 时间，不将参数变化和结构变化混为一次实验。

## 实验顺序与评价

1. 完成默认全参数 MoT 的端到端基线，记录配置、数据和权重版本、训练 loss、显存/内存、每维度得分、失败视频及延迟。
2. 用相同设置比较无历史、历史状态、历史动作、两者组合；先在预先固定的开发任务/种子上筛选。
3. 与无历史基线独立比较一次计算的未来条件；再测试稀疏交互或未来监督，不同时引入多种新机制。
4. 对有效模型进行去噪步数和系统性能测试，再考虑蒸馏。组合多个改进前先证明各自作用。
5. 冻结选择后按官方协议进行完整评测，保存逐任务、逐种子、每维度的原始结果、成功率、score、训练配置和 checkpoint/统计量哈希。开发调参与最终报告分开，局部结果不作为官方完整成绩。

同时比较等训练窗口数和实际 GPU 时间；单卡能否完成全参数训练、方法能否提升 RoboDojo、模型是否可公开以及是否获官方认可，均需独立验证。增加模块、借鉴方法或更名本身不能证明原创性或榜单提升。
